NAME

nikhil - software engineer; runs fleets of coding agents that have to prove their work

SYNOPSIS

nikhil [--orchestrate fleet] [--verify everything] [--trust nothing unverified]

DESCRIPTION

Builds the systems around AI coding agents rather than just using them. One model orchestrates, others implement and review, each task routed to the cheapest tier that can handle the judgment required. The models are interchangeable. The enforcement layer is not, so that's where the effort goes: write leases handed out at dispatch, acceptance tests frozen before the implementer sees them, review verdicts limited to CONFIRMED, PLAUSIBLE, or REFUTED, and a permission model where commit does not imply push and push does not imply PR.

Operating principle: anything only a human can judge is either real judgment or a missing gate. Most of it is the second kind. Build the gate.

PROJECTS

agent gateway fork Forked an open-source agent gateway and built its missing enforcement layer: checkpointing with claim fencing (a successor can't take a card until its predecessor's PID exits), a fail-closed capability handshake between dispatcher and workers, comment-driven wake for blocked cards. Found the clone was shallow and 508 commits behind upstream; rebased onto real mainline before building. Decided the fork is the product; upstreaming is opportunistic.
pi-ui Terminal session browser and multiplexer. Scans the on-disk transcript stores of three different agent CLIs, groups sessions by project, resumes any of them live over a PTY. TypeScript run natively by Node, no build step.
swarm review pipeline Parallel read-only reviewer lanes emit candidate findings in a fixed format; one fresh verifier per candidate returns a verdict. The model that wrote the code is never its only reviewer.
workflow package The rules the whole fleet runs on, maintained as a versioned repo with a sync script that generates the copies each tool loads. Core rules stay repo-agnostic; per-repo detail lives in per-repo files so the general rules don't rot.

EXIT STATUS

Reports one of: PASS, FAIL, BLOCKED, or NOT RUN, with the reason. Never presents a skipped check as green.
