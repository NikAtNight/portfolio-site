Trust is a build artifact.
I make agents produce it.

Most of my recent work is getting AI coding agents to behave like professionals. Not smarter, that part is handled. I mean the boring virtues: prove what you did, stop when you're supposed to, leave evidence instead of a confident summary.

My setup is a small fleet. One model orchestrates, others implement and review, and each task goes to the cheapest tier that can handle the judgment involved. The models are commodities. The system around them is the work, and I've been building it in public view of exactly one user: me, at scale, every day.

The incident that started it

One ordinary review prompt once spawned five subagents, which recursively spawned 928 more. Three hundred sixty seven megabytes of transcripts from a single session. I could have written "be more careful" in an instructions file. Instead I concluded that prose doesn't constrain anything, and moved the caps on delegation depth and concurrency into harness config, where an agent can't talk its way past them.

That's the pattern in everything I build: when a rule fails, the fix is a mechanism, not a stronger sentence.

The audit

Do my agents actually follow the rules I wrote, or do I just believe they do? I mined every transcript on my machine, across four different tools, to find out. The first pass produced numbers I nearly trusted. An independent review found the methodology broken (replay copies inflating counts, prompts logged twice, most sessions machine-dispatched rather than mine), so I threw it out and did it properly.

The real findings: 460 commits and 281 pushes with zero unauthorized. Twenty six sessions that wrote files, claimed success, and never ran a test. Seven of my 43 installed agent skills had ever been used, so I deleted the other 36. And an honest caveat I kept in the report: the rules were written mid-period, so the earlier data can't prove they work.

Things I've built

An enforcement layer for an agent gateway
Forked an open-source agent gateway and added what it was missing: checkpointing with claim fencing, a fail-closed capability handshake, workspace leases at dispatch time. Discovered my clone was 508 commits behind upstream, rebased first, and proved the branch clean with a differential sweep: identical failure sets on both sides, zero caused by my diff.
pi-ui
A terminal session browser that scans the transcript stores of three agent CLIs and resumes any session live over a PTY. TypeScript, no build step, because a personal tool that needs a bundler is a personal tool you stop maintaining.
A two-phase review pipeline
Parallel read-only reviewer lanes emit candidates, then a fresh verifier per candidate rules confirmed, plausible, or refuted. The model that wrote the code never gets to be its only reviewer.

One rule, verbatim

"A gate that has only ever passed is a guess. Perturb what it should catch, confirm it fails with a readable diff and a non-zero exit, restore, confirm green."

If you nodded at that, we'll get along.
